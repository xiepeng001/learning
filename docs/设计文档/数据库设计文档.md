# 数据库设计文档

## 1. 数据库概述

### 1.1 数据库选择
- **数据库**: SQLite 3
- **选择原因**:
  - 轻量级，无需独立服务器
  - 适合中小型团队使用
  - 支持全文搜索 (FTS5)
  - 部署简单，维护成本低

### 1.2 设计原则
- 数据一致性和完整性
- 查询性能优化
- 存储空间效率
- 扩展性考虑

## 2. 数据表设计

### 2.1 用户表 (users)

**用途**: 存储系统用户信息

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,           -- 用户名，4-20字符
    email VARCHAR(100) UNIQUE NOT NULL,             -- 邮箱地址
    password_hash VARCHAR(255) NOT NULL,            -- bcrypt加密后的密码
    role VARCHAR(20) DEFAULT 'viewer' NOT NULL,     -- admin/editor/viewer
    avatar_url VARCHAR(255) DEFAULT NULL,           -- 头像URL，可选
    is_active BOOLEAN DEFAULT 1 NOT NULL,           -- 账户状态，1-激活，0-禁用
    last_login_at DATETIME DEFAULT NULL,            -- 最后登录时间
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,  -- 创建时间
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP,  -- 更新时间

    CONSTRAINT chk_role CHECK (role IN ('admin', 'editor', 'viewer')),
    CONSTRAINT chk_username_length CHECK (LENGTH(username) >= 4 AND LENGTH(username) <= 20),
    CONSTRAINT chk_email_format CHECK (email LIKE '%@%.%')
);
```

**字段说明**:
- `id`: 用户唯一标识
- `username`: 用户名，唯一
- `email`: 邮箱地址，用于登录和通知
- `password_hash`: 密码哈希值 (bcrypt)
- `role`: 用户角色 (admin/editor/viewer)
- `avatar_url`: 头像URL (可选)
- `is_active`: 账户是否激活
- `last_login_at`: 最后登录时间

**索引**:
```sql
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_role ON users(role);
```

### 2.2 文档表 (documents)

**用途**: 存储文档基本信息和元数据

```sql
CREATE TABLE documents (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title VARCHAR(255) NOT NULL,                    -- 文档标题，1-255字符
    filename VARCHAR(255) NOT NULL,                 -- 存储文件名
    original_filename VARCHAR(255) NOT NULL,        -- 原始文件名
    file_path VARCHAR(500) NOT NULL,               -- 文件存储路径
    file_size INTEGER NOT NULL,                    -- 文件大小(字节)
    mime_type VARCHAR(100) NOT NULL,               -- MIME类型
    file_hash VARCHAR(64) DEFAULT NULL,            -- 文件MD5哈希值
    description TEXT DEFAULT NULL,                 -- 文档描述
    visibility VARCHAR(20) DEFAULT 'team' NOT NULL, -- public/team/private
    view_count INTEGER DEFAULT 0 NOT NULL,         -- 查看次数
    download_count INTEGER DEFAULT 0 NOT NULL,     -- 下载次数
    author_id INTEGER NOT NULL,                    -- 作者ID
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP, -- 创建时间
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP, -- 更新时间

    FOREIGN KEY (author_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT chk_visibility CHECK (visibility IN ('public', 'team', 'private')),
    CONSTRAINT chk_title_length CHECK (LENGTH(title) >= 1 AND LENGTH(title) <= 255),
    CONSTRAINT chk_file_size CHECK (file_size > 0 AND file_size <= 10485760) -- 最大10MB
);
```

**字段说明**:
- `title`: 文档标题
- `filename`: 存储的文件名 (重命名后)
- `original_filename`: 原始文件名
- `file_path`: 文件存储路径
- `file_hash`: 文件哈希值，用于去重检测
- `content`: 提取的文本内容，用于全文搜索
- `visibility`: 可见性级别
- `download_count`: 下载次数统计
- `view_count`: 查看次数统计

**索引**:
```sql
CREATE INDEX idx_documents_author ON documents(author_id);
CREATE INDEX idx_documents_visibility ON documents(visibility);
CREATE INDEX idx_documents_created_at ON documents(created_at DESC);
CREATE INDEX idx_documents_mime_type ON documents(mime_type);
CREATE INDEX idx_documents_file_hash ON documents(file_hash);
```

### 2.3 标签表 (tags)

**用途**: 存储标签信息

```sql
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(50) UNIQUE NOT NULL,
    color VARCHAR(7) DEFAULT '#1890ff',  -- 标签颜色 (HEX)
    description TEXT,
    is_system BOOLEAN DEFAULT 0,  -- 是否为系统标签
    created_by INTEGER,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (created_by) REFERENCES users(id) ON SET NULL
);
```

**字段说明**:
- `name`: 标签名称，唯一
- `color`: 标签显示颜色
- `is_system`: 是否为系统预定义标签
- `created_by`: 创建者ID

**索引**:
```sql
CREATE INDEX idx_tags_name ON tags(name);
```

### 2.4 文档标签关联表 (document_tags)

**用途**: 文档和标签的多对多关系

```sql
CREATE TABLE document_tags (
    document_id INTEGER NOT NULL,
    tag_id INTEGER NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (document_id, tag_id),
    FOREIGN KEY (document_id) REFERENCES documents(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id) REFERENCES tags(id) ON DELETE CASCADE
);
```

### 2.5 文档权限表 (document_permissions)

**用途**: 文档的精细化权限控制

```sql
CREATE TABLE document_permissions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    document_id INTEGER NOT NULL,
    user_id INTEGER NOT NULL,
    permission VARCHAR(20) NOT NULL,               -- read/write/admin
    granted_by INTEGER NOT NULL,                   -- 授权者ID
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    expires_at DATETIME DEFAULT NULL,              -- 权限过期时间，可选

    UNIQUE(document_id, user_id),
    FOREIGN KEY (document_id) REFERENCES documents(id) ON DELETE CASCADE,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (granted_by) REFERENCES users(id),
    CONSTRAINT chk_permission CHECK (permission IN ('read', 'write', 'admin'))
);
```

**字段说明**:
- `permission`: 权限类型 (read/write/admin)
- `granted_by`: 授权者
- `expires_at`: 权限过期时间

**索引**:
```sql
CREATE INDEX idx_doc_permissions_document ON document_permissions(document_id);
CREATE INDEX idx_doc_permissions_user ON document_permissions(user_id);
```

### 2.6 收藏表 (favorites)

**用途**: 用户收藏的文档

```sql
CREATE TABLE favorites (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    document_id INTEGER NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(user_id, document_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (document_id) REFERENCES documents(id) ON DELETE CASCADE
);
```

### 2.7 操作日志表 (operation_logs)

**用途**: 记录用户操作行为，用于审计和统计分析

```sql
CREATE TABLE operation_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    action VARCHAR(50) NOT NULL,                   -- 操作类型
    resource_type VARCHAR(50) NOT NULL,            -- 资源类型(document/tag/user)
    resource_id INTEGER DEFAULT NULL,              -- 资源ID
    description TEXT DEFAULT NULL,                 -- 操作描述
    ip_address VARCHAR(45) DEFAULT NULL,           -- IP地址
    user_agent TEXT DEFAULT NULL,                  -- 用户代理
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    CONSTRAINT chk_action_length CHECK (LENGTH(action) >= 1),
    CONSTRAINT chk_resource_type CHECK (resource_type IN ('document', 'tag', 'user', 'auth'))
);
```

**字段说明**:
- `action`: 具体操作类型，如 'login', 'upload_document', 'delete_tag' 等
- `resource_type`: 操作的资源类型
- `resource_id`: 相关资源的ID，对于全局操作可为NULL
- `description`: 操作的详细描述

**索引**:
```sql
CREATE INDEX idx_operation_logs_user ON operation_logs(user_id);
CREATE INDEX idx_operation_logs_action ON operation_logs(action);
CREATE INDEX idx_operation_logs_created_at ON operation_logs(created_at DESC);
CREATE INDEX idx_operation_logs_resource ON operation_logs(resource_type, resource_id);
```

## 3. 全文搜索设计

```sql
-- 创建全文搜索虚拟表
CREATE VIRTUAL TABLE documents_fts USING fts5(
    title,
    content,
    description,
    content_id UNINDEXED,  -- 对应documents表的id
    tokenize = 'porter'
);
```

### 3.2 同步触发器

```sql
-- 插入触发器
CREATE TRIGGER documents_fts_insert AFTER INSERT ON documents BEGIN
    INSERT INTO documents_fts(title, content, description, content_id)
    VALUES (new.title, new.content, new.description, new.id);
END;

-- 更新触发器
CREATE TRIGGER documents_fts_update AFTER UPDATE ON documents BEGIN
    UPDATE documents_fts SET
        title = new.title,
        content = new.content,
        description = new.description
    WHERE content_id = new.id;
END;

-- 删除触发器
CREATE TRIGGER documents_fts_delete AFTER DELETE ON documents BEGIN
    DELETE FROM documents_fts WHERE content_id = old.id;
END;
```

## 5. 数据维护

### 5.1 清理策略

```sql
-- 清理30天前的操作日志
DELETE FROM operation_logs WHERE created_at < datetime('now', '-30 days');

-- 清理已删除用户的相关数据 (通过外键级联删除实现)

-- 清理孤儿标签 (没有关联文档的标签)
DELETE FROM tags
WHERE is_system = 0
AND id NOT IN (SELECT DISTINCT tag_id FROM document_tags);
```

### 5.2 统计视图

```sql
-- 文档统计视图
CREATE VIEW document_stats AS
SELECT
    d.id,
    d.title,
    d.view_count,
    d.download_count,
    COUNT(f.id) as favorite_count
FROM documents d
LEFT JOIN favorites f ON d.id = f.document_id
GROUP BY d.id;

-- 用户统计视图
CREATE VIEW user_stats AS
SELECT
    u.id,
    u.username,
    COUNT(DISTINCT d.id) as document_count,
    COUNT(DISTINCT f.id) as favorite_count,
    SUM(d.file_size) as storage_used
FROM users u
LEFT JOIN documents d ON u.id = d.author_id
LEFT JOIN favorites f ON u.id = f.user_id
GROUP BY u.id;
```

## 6. 性能优化

### 6.1 查询优化建议

1. **分页查询**: 使用 LIMIT 和 OFFSET
2. **条件索引**: 为常用查询条件建立索引
3. **避免SELECT \***: 只选择需要的字段
4. **使用EXPLAIN**: 分析查询执行计划

### 6.2 存储优化

1. **定期VACUUM**: 回收删除数据的空间
2. **PRAGMA设置**: 优化SQLite配置
3. **文件分离**: 大文件存储在文件系统中
