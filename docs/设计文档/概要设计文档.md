# 团队知识库管理工具 - 概要设计文档

## 1. 设计概述

### 1.1 文档目的
本文档描述团队知识库管理工具的概要设计，包括系统整体架构、核心功能模块设计和关键技术方案。

### 1.2 设计原则
- **简洁性**: 功能简单明确，易于使用和维护
- **可扩展性**: 模块化设计，便于后续功能扩展
- **安全性**: 完善的权限控制和数据保护
- **性能**: 优化查询和文件处理性能

### 1.3 系统目标
- 提供简单易用的文档管理功能
- 支持快速的标题搜索和标签筛选
- 实现基础的用户权限管理
- 确保系统稳定可靠运行

## 2. 系统架构设计

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    用户界面层 (Frontend)                      │
│                React + TypeScript + Ant Design              │
└─────────────────────────┬───────────────────────────────────┘
                          │ HTTP/HTTPS + JSON
┌─────────────────────────▼───────────────────────────────────┐
│                    API服务层 (Backend)                       │
│                   FastAPI + Python                          │
├─────────────────────────────────────────────────────────────┤
│  认证模块  │  文档模块  │  搜索模块  │  标签模块  │  用户模块  │
└─────────────────────────┬───────────────────────────────────┘
                          │ SQLite Driver
┌─────────────────────────▼───────────────────────────────────┐
│                    数据存储层 (Database)                     │
│                       SQLite 3                              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 技术架构
- **前端框架**: React 18 + TypeScript + Vite
- **UI组件库**: Ant Design
- **状态管理**: Redux Toolkit
- **后端框架**: FastAPI + Python 3.9+
- **数据库**: SQLite 3
- **文件存储**: 本地文件系统
- **身份认证**: JWT Token

## 4. 数据设计

### 4.1 核心数据实体

#### 4.1.1 用户实体 (User)
```python
class User:
    id: int                    # 用户ID
    username: str             # 用户名
    email: str               # 邮箱
    password_hash: str       # 密码哈希
    role: str               # 角色(admin/editor/viewer)
    created_at: datetime    # 创建时间
    updated_at: datetime    # 更新时间
```

#### 4.1.2 文档实体 (Document)
```python
class Document:
    id: int                    # 文档ID
    title: str                # 文档标题
    filename: str             # 文件名
    file_path: str           # 文件路径
    file_size: int           # 文件大小
    mime_type: str           # 文件类型
    description: str         # 文档描述
    visibility: str          # 可见性
    author_id: int           # 作者ID
    created_at: datetime     # 创建时间
    updated_at: datetime     # 更新时间
```

#### 4.1.3 标签实体 (Tag)
```python
class Tag:
    id: int                    # 标签ID
    name: str                 # 标签名称
    color: str               # 标签颜色
    created_at: datetime     # 创建时间
```

### 4.2 数据关系
- 用户与文档: 一对多关系 (一个用户可以创建多个文档)
- 文档与标签: 多对多关系 (一个文档可以有多个标签，一个标签可以关联多个文档)

## 5. 安全设计

### 5.1 身份认证
- **JWT Token**: 无状态认证，包含用户ID和角色信息
- **密码加密**: 使用bcrypt进行密码哈希
- **Token过期**: 设置合理的过期时间，支持刷新机制

### 5.2 权限控制
- **角色权限**: Admin > Editor > Viewer
- **文档权限**: 基于可见性和用户角色的访问控制
- **API权限**: 每个接口进行权限验证

### 5.3 数据安全
- **输入验证**: 所有用户输入进行验证和清理
- **文件安全**: 上传文件类型和大小限制
- **SQL防护**: 使用ORM防止SQL注入

## 6. 性能设计

### 6.1 数据库优化
- **索引策略**: 为常用查询字段建立索引
- **分页查询**: 大数据量时使用分页
- **查询优化**: 避免N+1查询问题

### 6.2 文件处理
- **异步上传**: 使用异步处理提高响应速度
- **文件去重**: 通过哈希值避免重复存储
- **存储优化**: 合理的目录结构管理

### 6.3 前端优化
- **代码分割**: 按路由分割代码包
- **缓存策略**: 合理使用浏览器缓存
- **组件优化**: 使用React.memo等优化手段

## 7. 接口设计规范

### 7.1 RESTful API设计
- 使用标准HTTP方法 (GET/POST/PUT/DELETE)
- 统一的响应格式
- 合理的状态码使用

### 7.2 响应格式
```json
{
  "success": boolean,
  "data": object | array,
  "message": string,
  "error": {
    "code": string,
    "message": string
  }
}
```

### 7.3 错误处理
- 统一的错误代码定义
- 友好的错误信息提示
- 详细的日志记录

## 8. 部署架构

### 8.1 本地开发环境
- 前端: Vite开发服务器 (端口3000)
- 后端: Uvicorn开发服务器 (端口8000)
- 数据库: SQLite文件
- 文件存储: 本地uploads目录

### 8.2 本地生产环境
- 前端: 静态文件构建后直接访问
- 后端: Uvicorn生产模式运行
- 数据库: SQLite文件 + 手动备份
- 文件存储: 本地文件系统

### 8.3 部署要求
- **硬件要求**:
  - CPU: 2核心以上
  - 内存: 4GB以上
  - 存储: 50GB以上可用空间
- **软件要求**:
  - Python 3.9+
  - Node.js 18+
  - 现代浏览器支持
- **网络要求**:
  - 本地网络访问
  - 可选：局域网内其他设备访问
